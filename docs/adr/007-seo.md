# ADR-007: SEO approach

- **Status:** Accepted  
- **Date:** 2026-08-31 (accepted 2026-09-01)

## Context

NFR-12 ([requirements.md](../requirements.md)) asks for strong SEO from the beginning on public and Learn content. Keyword themes, URL targets, AI-era content shape, and technical checklist live in [seo-plan.md](../seo-plan.md). The web app is Angular and leaned on client-side rendering. Crawlers, link previews, and AI answer systems need real titles and text for Learn units.

Lab `/lab` is an editor — little SEO value.

## Decision

1. **Learn + marketing pages** are the SEO surfaces: unique titles, meta description, semantic HTML, stable URLs (`/learn/{moduleSlug}/{unitSlug}`). IA: [learn-ia.md](../learn-ia.md).
2. **Prerender** Learn routes at build time via `@angular/ssr` + `app.routes.server.ts` (`RenderMode.Prerender` for `/learn` and each catalog unit). **Lab, Account, and other routes use `RenderMode.Client`** (localStorage, canvas).
3. **`/lab` and `/account`:** `noindex, nofollow` via `Meta` in page components.
4. **Structured data** — `LearningResource` + `HowTo` JSON-LD on all Learn unit pages; `CollectionPage` on hub. Generated at render/prerender via `LearnSeoService`.
5. **Canonical URLs**, Open Graph tags, `sitemap.xml` and `robots.txt` — built by `scripts/generate-seo-files.mjs` before `ng build` (set `SITE_ORIGIN` for production).
6. **AI-era content:** unit pages use quotable structure (summary, numbered steps, pitfalls in copy) per seo-plan.
7. i18n: `hreflang` when we add locales; EN-only first.

Title/meta: `LearnSeoService` sets document title and description from i18n strings.

## Consequences

- Learn IA favours shareable, stable URLs ([risks-and-deferrals.md](../risks-and-deferrals.md))
- Build produces static HTML for Learn hub and units under `dist/web/browser` via `prerender-routes.txt` (sync with `learnPrerenderPaths()`)
- Slightly more front-end build complexity than pure CSR
- New Learn units must be added to `LEARN_UNITS` and are picked up by `getPrerenderParams`
